# NANO MESH 客户端 · 访问认证与本地安全方案（评审稿）

> 状态：**设计评审稿，未落地**。评审通过后再按「分期路线」实现。
> 适用：`clients/app`（Tauri 桌面/移动端主程序）。
> 目标读者：项目负责人评审。

---

## 1. 背景与现状

当前 Tauri 客户端**无任何访问限制**：

- 任何人打开 App 即进入启动页，可**选择/新建任意用户身份（公钥）**、连接节点、收发消息、查看实体目录。
- 用户身份的私钥种子以**明文**存放在应用数据目录 `identities/<公钥>.seed`（32 字节，仅 unix 0600 权限）。
- 只要能读到这些文件，即可**完整窃取身份**（在别处冒充该公钥登录、收发消息、行使其权限）。

需要澄清的边界：**传输链路本身已安全**。iroh 的 QUIC/TLS 握手在传输层证明「对端持有其公钥」，连接身份是被密码学认证的（见 `crates/nm-crypto` 顶部注释）。因此本方案**不涉及网络认证**，只解决**本地访问控制与私钥静态保护**——也正是那段注释里「登录退化为本地问题」留下的缺口。

---

## 2. 威胁模型

### 在范围内（本方案要防的）
| 威胁 | 说明 |
|---|---|
| T1 无人值守/共享设备被他人操作 | 别人趁 App 开着或直接打开，冒用你的身份收发消息 |
| T2 私钥文件被拷走 | 拷贝 `identities/*.seed` → 在别处完整复活该身份 |
| T3 磁盘/备份泄露 | 磁盘镜像、云同步、误备份导致明文私钥外泄 |
| T4 身份误用（多账号串号） | 想用「工作号」却被人用了「生活号」，或反之 |

### 不在范围内（本方案不管的）
- 网络中间人 / 冒充节点：iroh 传输层已解决（公钥认证 + 端到端密文中继）。
- 有 root/内核级恶意软件的主机：可读进程内存，任何本地方案都无法根治（仅靠自动锁定 + 内存清零缓解）。
- 端到端消息加密（E2EE）：属于协议层议题（`nm-crypto` 规划的 openmls），与本地访问认证正交，另案。

---

## 3. 设计目标与原则

1. **默认安全**：首启即强制设置访问口令；私钥**永不以明文落盘**。
2. **认证根唯一、可扩展**：以「主口令」为根，可叠加生物识别/PIN 作为便捷解锁，但根始终是口令。
3. **去中心一致**：无中心服务器，**不做「找回密码=服务端重置」**；找回只能靠用户自持的备份/恢复码。
4. **低摩擦**：日常一次解锁即可用全部身份；生物识别一键解锁。
5. **可分期**：P1 就能显著提升安全（口令门 + 种子加密），生物识别/自动锁定等增量叠加。
6. **复用既有栈**：KDF/哈希优先用仓库已有的 `argon2` / `blake3`，签名沿用 iroh Ed25519。

## 4. 方案总览（分层）

```
┌─────────────────────────────────────────────┐
│ A. 应用解锁门（主口令 / 生物识别）            │  ← 打开 App 的第一道关
├─────────────────────────────────────────────┤
│ B. 身份私钥静态加密（信封加密，私钥永不明文） │  ← 拷走文件也没用
├─────────────────────────────────────────────┤
│ C. 会话与自动锁定（超时/失焦重新上锁 + 内存清零）│
├─────────────────────────────────────────────┤
│ D. 备份与找回（加密导出 / 恢复码，去中心自持） │
└─────────────────────────────────────────────┘
```

核心密码学结构（**信封加密 Envelope**，推荐）：

```
主口令 ──Argon2id(salt,params)──▶ 主密钥 MK
MK ──AEAD──▶ 解密 ▶ 保险库密钥 VK（随机 32 字节，仅解锁后在内存）
VK ──AEAD──▶ 加密 ▶ 每个身份种子 seed_i
校验值 verifier = AEAD_MK("nmspace-vault-v1")   // 用于快速校验口令对错，不必解密种子
```

- 改主口令**只需重新用新 MK 加密 VK**，不必逐个重加密种子。
- 解锁 = 用口令算 MK → 校验 verifier → 解出 VK（驻留内存）；上锁 = 清零 MK/VK。

## 5. 详细设计

### A. 应用解锁门

- **首启（未设主口令）**：进入**设置向导**——创建主口令（强度校验：≥8 位、含大小写+数字+特殊字符，可配）；提示「无中心找回，请牢记并做备份」。
- **已设、已上锁**：进入**解锁页**——输入主口令（或生物识别）。连续失败 N 次（默认 5）指数退避/冷却，抵御暴力破解（Argon2id 本身已慢，这是二重保险）。
- **已解锁**：进入现有「选择身份 + 节点服务 + 连接」启动页。
- 解锁门是**独立视图**，位于现有 `login-view` 之前；未解锁时不加载任何身份、不暴露任何命令数据。

### B. 身份私钥静态加密

- 存储从 `identities/<pubkey>.seed`（明文）改为**加密保险库**：
  - `vault.json`：`{ version, kdf:{alg:"argon2id", salt, m, t, p}, verifier(nonce+ct), wrapped_vk(nonce+ct) }`
  - `identities/<pubkey>.enc`：`{ nonce, ct }`（VK 加密的种子）+ 明文可留 `<pubkey>` 于文件名（公钥非机密）。
- **AEAD**：推荐 **XChaCha20-Poly1305**（RustCrypto `chacha20poly1305`，24 字节随机 nonce、无需 AES-NI、恒定时间）；备选 AES-256-GCM。
- **KDF**：**Argon2id**（仓库已有 `argon2` 0.6）。建议参数 m=64 MiB、t=3、p=1（移动端可下调，随设备量力）。参数入库，便于日后升级。
- 私钥仅在**连接建立瞬间**在内存解密给 `nm-client` 绑定；`zeroize` 及时清零，不长期驻留。

### C. 认证方式（可组合）

| 方式 | 说明 | 阶段 |
|---|---|---|
| 主口令（根，必选） | Argon2id 派生 MK，见 B | P1 |
| OS 生物识别 / 系统钥匙串 | 把 VK（或 MK）封存进 **macOS Keychain(Touch ID) / Windows Hello / Linux libsecret**，一键/刷脸解锁；口令仍是兜底根 | P2 |
| 数字 PIN（便捷） | 设备本地短 PIN 解一个「设备密钥」，设备密钥再解 VK；限次数、可被主口令重置 | P2（可选） |

> 生物识别拟用 `keyring` crate（跨平台封装）；根仍是主口令，生物识别只是解 VK 的便捷通道，丢设备不等于丢身份。

### D. 会话与自动锁定

- **自动上锁**：无操作超时（默认 10 分钟，可配）、窗口失焦/最小化（可配）、系统睡眠 → 清零内存密钥、断开连接、回解锁页。
- **手动上锁**：标题栏加「🔒 锁定」入口。
- 内存中的 MK/VK/解密种子一律 `zeroize`；避免序列化/日志泄露。

### E. 多账号与口令关系

- **默认**：主口令解锁**整个应用**，解锁后可用全部身份（低摩擦，符合「一人多号一次登录」的直觉）。
- **可选加固**：某个身份可**追加独立口令**（在其种子外再套一层该身份专属 AEAD），用于「工作号」这类需二次确认的账户——切到它时额外验一次。属 P2 可选项。

### F. 备份与找回（去中心，无服务端重置）

- **加密导出**：把（选定/全部）身份导出为一个**独立口令加密的备份文件**（Argon2id+AEAD，与主口令解耦），可存 U 盘/密码管理器。换机/重装靠它导入。
- **恢复码**（可选）：设主口令时生成一段一次性恢复码（如 BIP39 助记词包裹 VK），离线抄写；忘记主口令时用它重设。
- **明确告知**：**主口令 + 备份/恢复码全丢 = 身份永久丢失**（去中心无人能重置）。首启与改密处强提示。

## 6. 落地改动点（评审后实现，本次不动）

### 后端 `clients/app/src-tauri/src/lib.rs`
- 新增内存态：`Vault { unlocked: bool, vk: Option<Zeroizing<[u8;32]>> }`（放进 `AppState`）。
- 新增命令：
  - `auth_status() -> {master_set, unlocked}`
  - `setup_master(password) -> ()`（首启建库；把现有明文种子迁移加密）
  - `unlock(password) -> bool`
  - `lock() -> ()`
  - `change_master(old, new) -> ()`
- **改造**：`list_identities` / `create_identity` / `connect` 未解锁时一律拒绝（`Err("未解锁")`）；`create_identity`/`connect` 改为经 VK 加解密种子。
- 依赖新增（client 是独立 cargo 工程）：`argon2`、`chacha20poly1305`、`zeroize`、（P2）`keyring`、（可选）`bip39`。

### 前端 `clients/app/ui`
- 新增**解锁/设置视图**（`#lock-view`，位于 `#login-view` 之前）：首启设密向导 + 解锁页 + 失败冷却。
- 标题栏加「🔒 锁定」；`auth_status` 决定启动进哪个视图。
- 自动锁定：`visibilitychange`/失焦 + 空闲计时器 → `lock()` → 回解锁页。
- `js/auth.js`（新）：封装 setup/unlock/lock/status。

### 迁移
- 首次 `setup_master`：把已有明文 `identities/*.seed` 读入 → 用 VK 重新加密为 `.enc` → **安全删除**明文（覆盖写 + 删除）。给出「已加密 N 个身份」提示。

## 7. 依赖与选型小结

| 用途 | 选型 | 备注 |
|---|---|---|
| KDF | Argon2id（`argon2` 0.6，仓库已用） | 内存硬，抗暴力/GPU |
| 对称加密 | XChaCha20-Poly1305（`chacha20poly1305`） | 随机大 nonce、恒定时间、无 AES-NI 依赖 |
| 内存清零 | `zeroize` | 密钥/种子用后即清 |
| 生物识别/钥匙串 | `keyring`（P2） | mac Keychain / Win Hello / Linux libsecret |
| 恢复码 | `bip39`（可选） | 助记词包裹 VK |
| 哈希 | `blake3`（仓库已用） | verifier/校验等 |

签名/身份仍沿用 iroh Ed25519（`nm-transport::SecretKey`），不引第二套身份体系。

---

## 8. 分期路线

- **P1（最小可用，显著提升安全）**：主口令门 + 身份种子信封加密 + 明文迁移 + 手动锁定 + 命令门禁。→ 覆盖 T1/T2/T3 主体。
- **P2（便捷与加固）**：生物识别/钥匙串一键解锁、自动锁定、每身份可选独立口令、加密导出/导入备份。
- **P3（可选）**：恢复码（助记词）、失败冷却策略细化、移动端 KDF 自适应、审计日志。

## 9. 需你拍板的决策点（评审时确认）

1. **认证根**：主口令解锁**整个应用**（推荐，低摩擦） vs 每身份独立口令（更强隔离，更繁琐） vs 两者结合（默认主口令 + 敏感号追加）。
2. **生物识别**：P2 是否要接入 Touch ID/Windows Hello（需 `keyring` 依赖）？
3. **找回策略**：接受「无找回，仅靠加密备份/恢复码」（最安全，去中心一致）？是否要恢复码（助记词）？
4. **自动锁定默认值**：空闲超时时长、是否失焦即锁。
5. **口令强度策略**：沿用门户那套（≥8 + 大小写 + 数字 + 特殊字符）还是自定义。
6. **AEAD 选型**：XChaCha20-Poly1305（推荐） vs AES-256-GCM。
7. **落地范围**：先只做 P1 上线，还是 P1+P2 一起？

---

## 10. 一句话结论

现状是「传输已加密、**本地全裸**」。本方案用**主口令解锁门 + Argon2id/XChaCha20 信封加密身份私钥 + 自动锁定 + 去中心加密备份**补上本地这道关；P1 即可让「拷走文件」「顺手打开」都失效，且不引入中心化依赖。评审确认第 9 节决策点后，我按 P1 先落地。
